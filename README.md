# tsp-app

巡回セールスマン問題 (TSP: Traveling Salesman Problem) を解く Android アプリです。画面の盤をタップして都市を置き、解き方を選んで「解く」を押すと、全ての都市を 1 回ずつ訪れて出発点に戻る道を描き、その長さと、かかった時間を表示します。

## 使い方

- 盤をタップすると、その位置に都市を置きます。最初に置いた都市 (橙の大きな点) が出発点です。
- 「ランダム」は、スライダーで決めた数 (4 から 60) の都市を、でたらめに置き直します。
- 「消去」は、全ての都市を消します。
- 解き方を選んで「解く」を押します。解いている間は、上に横棒を出します。

## 解き方

| 解き方 | 内容 | 計算の量 | 最短か |
|:---|:---|:---|:---|
| 最近傍 | 出発点から、最も近い、まだ訪れていない都市へ、順に進む | n² | 最短とは限らない |
| 2-opt | 最近傍の道で、交差する 2 本の辺を、短くなるようにつなぎ替える。短くできなくなるまで繰り返す | 1 周で n² (繰り返す) | 最短とは限らない (交差のない道になる) |
| 厳密解 | 動的計画法 (Held-Karp)。「出発点から、ある都市の集合を全て訪れて、都市 j で終わる道」の最短を、集合の小さい順に求める | n² × 2ⁿ | 最短 (12 都市まで) |

n は都市の数です。厳密解は、都市が 12 より多いと、使えません (計算の量と、メモリが、急に増えるため)。

## 構成

- `core`: 純粋な Kotlin。点、距離、巡回路の長さ、3 つの解き方、でたらめな点 (`core/src/main/kotlin/jp/tspapp/core/Tsp.kt`)。単体テストで、行と分岐のカバレッジは 100% です。厳密解は、小さな問題で、全ての順を試した最短と比べて確かめています。
- `app`: Android の画面。都市を置いて道を描く盤 (`TourView`)、画面 (`MainActivity`)、ログ (`AppLog`)。画面は Material 3 の配色 (ライトとダーク) で、端末の言語が日本語なら日本語、それ以外は英語で表示します。

## 開発

Android Studio は使いません。ビルド、テスト、整形、静的解析、ドキュメントの生成は全てコマンドラインで、Docker の中で実行します。手順は [SETUP.md](SETUP.md) です。作りは [gaia-neko](https://github.com/sluchin/gaia-neko) と同じです。
